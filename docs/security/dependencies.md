# Dependency and install review

Checked 2026-10-01 with Node.js 26.8.2 and npm 11.19.1. All direct versions are exact; the first successful install produced package-lock.json. npm ci reproduced the tree; npm audit reported zero vulnerabilities.

## Install policy

[.npmrc:1](../../.npmrc#L1) disables lifecycle scripts before installation. [.npmrc:2](../../.npmrc#L2) sets seven days. npm 11.19.1 supports this setting in days, as documented in [npm configuration](https://docs.npmjs.com/cli/v11/using-npm/config/#min-release-age). No age exclusion or peer-resolution bypass is configured. [.npmrc:6](../../.npmrc#L6) refuses git dependencies, which the age floor cannot date.

**Electron is the one package allowed to run an installer.** npm run setup:electron explicitly invokes node_modules/electron/install.js because Chromium and the executable are downloaded separately. The inspected package has no automatic install lifecycle hook; its standalone installer checks the archive against checksums.json. [scripts/setup-electron.mjs:1](../../scripts/setup-electron.mjs#L1) keeps its cache inside .npm-cache/electron. Every other lifecycle script stays disabled. The optional macOS fsevents package has an install script in the lockfile; it is neither installed nor allowed to build on the supported targets.

Each normal persistent profile gets one ElectronChromeExtensions instance before extensions load. Private sessions receive neither its instance nor its frame/worker preload. Horizon's own tab and window owners implement creation, selection, removal and navigation. Dormant pages remain unloaded; when extensions are enabled, hidden views provide stable tab IDs, including Home, Settings and Desktop tabs. Those placeholders never cover chrome pages. Toolbar actions read the library's per-tab icon, title and badge state and invoke its popup or onClicked support through Horizon's existing validated command channel. Icons use bounded PNG bytes and blob URLs; the vendor's remote-partition bridge, crx protocol and browser-action custom element are not exposed to chrome. React supplies the existing token styles and keyboard targets without weakening the CSP.

`scripts/package-chrome-extensions.mjs` packages reviewed copies beside the main entry point and checks their SHA-256 hashes before applying guarded substitutions. The extension preload obtains the frame or worker URL and runs only for a credential-free chrome-extension URL with a valid extension ID. Ordinary pages, Web Store pages and web service workers get no bridge. Main routing verifies that the calling frame or worker belongs to the claimed loaded extension in its own session. Remote partition routing and native messaging are denied. Vendor debug and console logging are suppressed locally without editing node_modules or affecting Horizon's logs. Resource paths must stay below the extension directory, and popups must belong to that extension. The library does not replace Horizon's session request or permission handlers.

Horizon adds profile-scoped alarms with bounded names/counts, worker event delivery, cancellation on unload and timers held in main while workers sleep. Alarm state is transient across application restarts; extensions must recreate it on startup. Suggested extension commands run in the selected page, and Horizon shortcuts retain priority. API support remains partial: action enable/disable and MV3 imageData icons, contextMenus.update, some notification/navigation events and tabs methods are absent in 4.9.0. Warnings no longer list action, commands, alarms, contextMenus, cookies, notifications or webNavigation. They retain declarativeNetRequest, offscreen, userScripts, managed policy storage, history, bookmarks, sessions, fontSettings and other missing APIs. webRequest permissions also warn because Horizon's session request hooks mask the native listeners. The runtime verifier names uBlock Origin Lite as the unsupported-warning sample and requires its worker and action, Dark Reader's worker and a changed local page, and Vimium's worker even when a sample has a warning. Electron runtime execution is still required outside the sandbox.

The 0.13.0 preload uses a hostname prefix, runs in subframes and enables debug output. The build copies its pinned source into `dist/electron/store-preload.js`, disables debug output and places the entire bridge behind an exact HTTPS origin and main-frame guard. It copies the pinned CommonJS distribution into `dist/electron/web-store.cjs`, disables its four debug loggers so an inherited DEBUG variable cannot expose store payloads, and resolves its preload to that guarded copy. Build assertions reject a vendor source change requiring a fresh review. No installed package files are edited. Only normal profile sessions register it. Its global IPC handlers are additionally restricted to an owned Web Store main frame in that same profile session; login data never reaches vendor handlers. The vendor's automatic loading and updating are disabled so Horizon's persisted enabled state and permission decisions remain authoritative.

The package captures its downloader at module initialization. Horizon supplies a bounded downloader only during that synchronous capture and immediately restores the process default. Downloads use HTTPS without credentials, fixed Google update and CRX hosts, approved Google icon hosts, a 45-second deadline, at most five approved redirects, 64 MiB per CRX and 1 MiB per icon. Google can observe extension IDs and the connection's IP address; the bilingual install dialog discloses that, developer data collection and the user's responsibility for trusting it. The default package matches the requested ID to a public key but does not check its signature. Horizon verifies the matching publisher's SHA-256 signature against the requested ID, signed header and archive before unpacking. Only CRX3 is accepted, following [Chromium's CRX3 format](https://chromium.googlesource.com/chromium/src/+/main/components/crx_file/crx3.proto). This establishes package integrity and publisher identity; it does not establish that an extension's behavior is benign.

Updates cannot downgrade an installed version. Added or changed API permissions, host access or content-script matches require a new warning decision; an inactive profile defers those updates until it has a normal owner able to answer. Other updates can run at startup only while a normal window exists. Downloaded staging directories are removed after every decision. Disabled extensions remain installed without loading code, and extension code is never loaded with local file access enabled.

The 2026-10-07 `npm audit --json` result first reported three high-severity affected packages: adm-zip 0.5.18, electron-chrome-web-store through adm-zip, and development-only source-map-js 1.2.1. adm-zip is overridden to 0.6.1, published 2026-09-11 and outside the affected range of [GHSA-7q85-xj36-vmfc](https://github.com/advisories/GHSA-7q85-xj36-vmfc); the extension runtime check passes with it, and the audit then reports only source-map-js. Before the pinned extractor receives an archive, Horizon rejects traversal and platform-special paths, duplicate or ambiguous names, links and special Unix modes, alternate Unicode path fields, ZIP64, encrypted or unsupported compression, oversized manifests, excessive entry counts and overlapping entries. It inflates each entry with a strict output cap, confirms its actual size and CRC, and limits expanded content to 256 MiB and individual files to 32 MiB. Extraction uses a new private staging directory and checks destination ancestors for links. Security tests cover hostile archives, including a compressed payload falsely declaring zero size. This reduces the input exposure associated with the [symlink extraction advisory](https://github.com/advisories/GHSA-vwc7-r8mq-g2x9) and [decompression-bomb advisory](https://github.com/advisories/GHSA-rcw4-f5rp-g42v); it does not change npm's package-level advisory result. The [source-map-js advisory](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) remains unresolved in the existing build toolchain.

On 2026-10-07 `npm audit fix` moved development-only source-map-js to 1.2.2, outside [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q). Its GitHub token reads run details and artifacts (`actions: read`); publishing uses only the run's own token (`contents: write`). Checkout credentials are not persisted. No new npm dependency was added: js-yaml and electron-builder's own external gzip blockmap tool come from the existing locked development tree. The artifact configurations must sign only Horizon's executable and installer and preserve upstream files, as documented in the release routine. The policy requires GitHub-hosted runners, refuses reruns and checks deletion/non-fast-forward rulesets. Manual approval, MFA, default-branch restrictions and artifact metadata restrictions are configured in SignPath by the owner before enabling signing.
