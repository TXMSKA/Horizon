## Favicon request boundary

[favicon.ts](../../electron/favicon.ts) makes outbound requests through each tab's own session, accepting only bounded HTTP/HTTPS URLs without credentials. Redirects are followed manually (at most five) and every target is checked before requesting it. Each candidate has a five-second abort timeout; navigation, replacement and tab closure abort pending work. The 256 KB cap is checked against the response header and enforced while reading the stream. SVG MIME types and bytes without a raster signature are rejected. The main process never decodes, resizes or re-encodes untrusted images: validated bytes reach a local blob URL and only the sandboxed chrome renderer decodes them at 16 by 16. A raster signature validates the format boundary, not whether the image can be rendered. Failures keep the initial badge.

Candidates and every redirect hop must use the page's own host or a public host. Other hosts refuse loopback, private, link-local, carrier-grade NAT, unique-local IPv6 and unspecified IP ranges, including IPv4-mapped IPv6 and the metadata address `169.254.169.254`, and `localhost`, `*.localhost`, `*.local`, `*.internal`, `*.lan` and `*.home.arpa`. Residual: a public name that resolves to a private address is not resolved here; this has the same reach as the page's own images.

[browser.ts](../../electron/browser.ts) publishes only a short hash, serves bytes through a sender- and argument-validated invoke, and clears cached icons on a change of site or tab closure. Chrome creates local blob URLs and revokes them on replacement or teardown. Node tests cover URL filtering, redirects, byte limits, SVG/non-image rejection, unchanged raster bytes without privileged decoding, stale results and IPC validation; native rendering remains for the seat to inspect.

App-wide themes use a separately validated, capped, atomically written `settings.json`, with corrupt originals preserved. The sandboxed preload validates the initial theme and contrast arguments. Old settings migrate to standard contrast; a missing file defaults to high contrast only when the OS requests it. Both settings reach the renderer before its first paint; System follows the OS without changing `nativeTheme.themeSource` or web page colour preferences.

## Page context-menu boundary

Every tab's `context-menu` event is handled in the main process. Chrome receives a fresh menu ID, the point converted to chrome CSS pixels, the keyboard source flag, grouped item IDs with enabled states, and at most 40 selected characters for the search label. Spelling item IDs include their display word; replacement still uses an exact match from the retained suggestions. Link and image URLs, full selections, edit flags and image coordinates stay in the main process. Every URL action passes `isWebURL`; image saving enters the existing Downloads flow. A new menu, navigation in any frame, tab switch, tab closure, page failure or dismissal invalidates the pending action.

The page menu shares the browser menu's React component, keyboard handling and popover styles. Its position uses CSSOM assignments under the unchanged CSP, and the page uses the existing bounded snapshot flow. Node tests cover item groups, unsafe URLs, limited display data, stale and disabled commands, saved-parameter actions, foreground and background tabs, editing, folder paths and lifecycle invalidation. Native placement, keyboard focus and visual parity remain for the seat's inspection; this run does not launch the app.

## Profile storage and deletion

[profiles.ts](../../electron/profiles.ts) validates the entire capped, atomically written `profiles.json` registry: exact shapes, UUIDs, unique persistent partitions, trimmed case-insensitively unique names, eight named colours, timestamps, the 20-profile cap, the active profile and non-overlapping tombstones. Invalid originals are moved aside. First run creates Personal and Work in the app language. Personal uses `persist:web` so existing sign-ins remain. The legacy `browser-store.json` is validated with the existing store reader, written to Personal's folder and renamed to `browser-store.json.migrated` with owner-only permissions (0600) only after that write succeeds. An existing archive is replaced so the old data remains recoverable; retries preserve newer profile data.

Each profile has a separate `profiles/<id>/browser-store.json`, encrypted through Electron's [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) when encryption is available. [store.ts](../../electron/store.ts) accepts an injected cipher for tests, caps reads and writes and validates decrypted data with the existing schema. Failed decryption or validation moves the original aside before creating an empty store and raises a read error in chrome, distinct from a save error. If an existing encrypted file cannot be read because encryption is unavailable, it stays untouched; that profile uses memory for the session and never writes plaintext over it. When encryption is unavailable from the start, Linux without a usable keyring keeps plain JSON with owner-only file permissions (0600) and directory permissions (0700), as Chrome does with its history. The owner accepted this decision on 2026-10-01. These are OS account protections; profiles are browsing contexts, not separate OS users.

Deletion refuses the last profile. It first writes the registry with the profile removed, a replacement active profile if needed, and the partition recorded as a tombstone. A failed write leaves everything unchanged and reports the error. After that, tab closure, download cancellation, scheduled-write cancellation, session storage, connection and cache clearing, and store-folder removal are best-effort. Failures are logged as storage errors and deletion still succeeds. At the next startup, before any profile session is created, tombstones remove their validated child folders under `sessionData/Partitions/` and remaining orphan profile-store folders. Root and leaf junctions or symlinks are refused, and a failed cleanup keeps the tombstones for retry.

The layout was confirmed in [Electron 44.4.5's browser context source](https://github.com/electron/electron/blob/v44.4.5/shell/browser/electron_browser_context.cc#L358-L365): persistent partitions append `Partitions` and the lowercase, path-escaped suffix after `persist:`. Horizon's allowed names need no escaping, so `persist:web` maps to `Partitions/web` and `persist:profile-<uuid>` to `Partitions/profile-<uuid>`. Cleanup tests cover the actual layout, protected live partitions, traversal and junction escapes.

## Fuse boundary for task 012

The prepared script requires resources/app.asar and runs before code signing. It disables RunAsNode, NodeOptions, Node CLI inspection, and file-protocol extra privileges; enables cookie encryption, ASAR-only loading, and Wasm trap handlers; enables embedded ASAR integrity for Windows binaries only; and selects the browser-specific V8 snapshot only when that artifact exists. All fuse options are explicit, and newly introduced fuses cause a hard failure.

The development binary lacks the browser-specific snapshot, so flipping that fuse there breaks startup, and Smart App Control blocks a modified binary; the script therefore refuses unpackaged targets. Task 012 owns ASAR creation, Windows integrity metadata, signing, and applying the script to distributable binaries.

Node tests exercise hostile IPC identities and arguments, bounded page capture, chrome/web frame navigation boundaries, URL/search classification, error names, default permission/device denial, protocol traversal and CSP, store schema/recovery, debounced writes and shutdown flushes, download name collisions and transient tabs, shared shortcuts, popup adoption, destroyed tabs and fullscreen in a mocked browser lifecycle. Run `npm run lint`, `npm run typecheck`, `npm run build` and `npm run test:security`. Build checks the theme contrast pairs. The task 001 integration script covers the foundation; it is not a browsing or profiles acceptance test. Native profile focus, visual board parity, OS encryption and Linux operation remain for the seat to inspect; this run does not launch the app.
